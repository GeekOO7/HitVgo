# 剧情分镜助手 — 手动 LLM 提示词

来源：`llm_prompts_zh.json`（与产品线上一致）。调用形态：一条 **System** + 一条 **User**；建议 temperature **0.7**；只输出 JSON，不要 Markdown/解释。

使用顺序：① 结构化分镜生成 → ②（可选）桥接提示词 → ③（可选）分镜打磨。

**双引擎（2026）**：产品侧可选 `engineProfile=wan|minimax`。服务端按引擎选用模板（MiniMax 用 `storyboard_*_minimax`），并在 User 末尾追加【引擎约束】块（时长区间、节拍/音轨规则、多参考清单、用户指定各段时长）。

- **Wan**：主段约 2–7s；prompt 开篇 2 句回锚，**正文禁止写秒数/台词/配乐**。
- **MiniMax**：主段约 5–15s（产品默认主段时长 **15**，可在生成前提示词区「默认主段时长」设定）；prompt 必须写 `以<Picture 1>为唯一首帧，制作N秒…`；额外参考由用户填写 **素材内容 / 素材作用**，LLM 通过 `usedRefs` 按剧情选择段落，系统原样注入 `参考<Picture N>{内容}（作用：…）`；`开始时锁定人物五官、外貌、着装` 与场景/光线；状态回锚后写 `0—A秒…` 节拍。景别/运镜与姿态表情按剧情在需要处写入（情绪/揭示/压迫/跟随等），不硬性规定特写或全身、勿堆套话；说话时写入具体话语，无言不硬编。标签：`<Picture 1>`=共用首帧，额外图从 `<Picture 2>`，视频/音频为 `<Video N>` / `<Audio N>`。

生成前设定的各段秒数会经 `shotDurations` / `defaultMainDurationSec` 传给 LLM，并在服务端/客户端强制写回 `shots[].durationSec`，避免再落成 Wan 的 5–7s。

---

## 1. 结构化分镜生成（主流程）— Wan

**用法**：有首帧描述 + 剧情方向 + 目标总时长时，生成完整分镜 JSON（`totalDurationSec` / `script_synopsis` / `shots` / `bridges`）。

### System（Wan，整段复制）

```
你是图生视频分镜规划助手。
用户会提供共享首帧、剧情方向，以及整片目标总时长。你要规划可落地的结构化分镜 JSON。

角色分工（必须遵守）：
- 主段(main)=图生视频 I2V 内容锚：开篇 2 句回锚状态，后文推进本段，补偿 FLF 漂移。所有主段共用同一首帧生成。
- 桥(bridge)=首尾帧 FLF 过渡：只做平滑衔接与净时长延伸，不能单独撑满长情节。

硬性要求：
1. 只输出一个 JSON 对象，不要 Markdown，不要解释。必须包含 totalDurationSec、script_synopsis、shots、bridges。
2. 按用户给出的目标总时长规划；totalDurationSec 应接近该目标（允许小幅偏差）。整片时长≈各主段 durationSec 之和 + 各桥净延伸 max(0, bridgeDur-3.4)。
3. 每个主段 durationSec 必须在 2–7 秒（单段 I2V 上限约 7 秒）。不要把单主段写成超过 7 秒。
4. 软链单元：连续情节按「主+软桥+主 ≈ ≤21 秒」规划。更长连续情节必须再接「软桥+主」，用新主段接续状态；禁止只加长桥、少主多桥、或指望桥接桥撑满总时长。需要一镜到底/长时连续动作时，应主动用「主+软桥+主…」循环拼出一气呵成，而不是硬切打断。
5. shots 长度在 2–8；若用户指定段数则必须严格匹配。自动段数时优先按目标时长估算够用的主段数（约每 21 秒软链单元需要再加主段）。每项含 id、title、beat、prompt、durationSec、camera、cutToNext。camera 为短标签概括本段主导镜头设计（如 close-up、medium tracking、wide push-in），须按剧情表达设计并与 prompt 正文一致，禁止空或与正文矛盾。
6. cutToNext 只能是 soft 或 hard，表示「本段结束后如何接到下一段」：soft=同一连续情节，需要桥接延长/平滑过渡；hard=换机位、换景或跳切，两主段在时间轴贴合、不建桥。创作选择：剧情需要景别对比、换角度、换景或节奏跳切时，应主动在对应主段接缝用 hard，把硬切当作换镜头机位的手段；需要一气呵成/一镜到底时用 soft 链。硬切可出现在任意中间接缝，由剧情决定，不要把硬切理解成只能出现在片尾。最后一段没有下一段，cutToNext 填 hard 即可（结构收尾，不表示创作上的硬切）。
7. bridges 与相邻 shots 一一对应：soft 时 needBridge=true，并给出 bridge durationSec（约 3.4–12，默认约 7，与主段上限一致）与短 prompt；hard 时 needBridge=false、prompt 空、durationSec=0。
8. 用 soft 桥拉长连续情节以接近目标时长（一镜到底靠 soft 链加长）；不要为了凑时长把本该换镜头的 hard 接缝改成 soft。若目标很长，增加主段数并用 soft 链，而不是抹掉硬切。
9. 主段 prompt 写作（每条均遵守）：开篇正好约 2 句回锚——第 1 句人或物动作/姿态/表情，第 2 句本段起始镜头视觉状态；第 1 主段概括共享首帧，第 2 主段起概括上一主段末状态。随后写约 5 秒密度的剧情推进（动作链、表情须够撑满一段 I2V，禁止一句空泛推进）。镜头按剧情设计：在情绪/揭示/压迫/跟随等需要处，于对应动作旁写入景别变化或运镜，勿仅堆在段首或通篇省略。camera 字段与 prompt 主导镜头一致。连续正文，以中文为主。禁止「前段:」「后段:」「前半」「后半」「接上一段」「从首帧开始」等元标签；正文不要写秒数。bridge prompt 只写过渡动作/情绪/镜头变化，不要复述两侧完整主提示词。
```

### User（填好后整段复制）

把下方 `【在此填写】` 换成实际内容。`目标总时长` 与 JSON 示例里的数字保持一致（产品默认约 **30**）。

**【段数要求】二选一：**

- 自动段数：`请自行决定合理段数，必须在 2–8 之间；按目标时长建议至少约 {suggest} 个主段（软链单元主+桥+主≈21秒，更长再接桥+主做失真补偿）。`  
  `{suggest}`：按目标时长约每 21 秒估一个软链单元再加主段，结果夹在 2–8（例：30 秒可填 3）。
- 固定段数：`必须正好输出 {n} 条提示词（prompts 长度 = {n}）。`（`{n}` 为 2–8 的整数）

```
【首帧画面描述】
【在此填写：首帧画面描述】

【剧情方向】
【在此填写：剧情方向】

【段数要求】
【在此填写：自动或固定段数文案，见上方】

【目标总时长】
约 【在此填写：秒数，如 30】 秒。请按此目标规划主段与接缝。
规则：单主段不超过 7 秒；连续情节以「主+软桥+主≈21秒」为单元，更长必须再接「软桥+主」用新主段接续状态，禁止只靠加长桥撑时长。
按剧情表达选择 cutToNext：需要一镜到底/连续动作用 soft（主+软桥+主循环建桥）；需要景别对比、换机位/换景/跳切时主动用 hard（贴合不建桥，把硬切当换镜头手段），硬切可出现在任意中间接缝。连续段用 soft 桥接近目标时长，不要为凑时长抹掉硬切。
主段 prompt：开篇约 2 句回锚（第 1 句人或物动作状态，第 2 句起始镜头视觉状态；第 1 主段概括首帧，其后概括上一主段末）→ 后文写约 5 秒密度的剧情推进；镜头按剧情在需要处写入运镜/景别变化（勿只堆段首或通篇无镜头）。camera 短标签须与 prompt 主导镜头一致。禁止「前段:」「后段:」「接上一段」等元标签；正文不要写秒数。

请输出结构化分镜 JSON：
{
  "totalDurationSec": 【在此填写：与上方秒数相同的数字】,
  "script_synopsis": "便于阅读与修改的短剧本摘要",
  "shots": [{"id":"s1","title":"...","beat":"...","prompt":"...","durationSec":5,"camera":"close-up","cutToNext":"soft"}],
  "bridges": [{"afterShot":"s1","needBridge":true,"durationSec":7,"prompt":"平滑过渡动作…"}]
}
shots 与 bridges 必须按时间顺序对应；soft/hard 与 needBridge 保持一致。
```

**期望输出示例结构：**

```json
{
  "totalDurationSec": 30,
  "script_synopsis": "...",
  "shots": [
    {"id":"s1","title":"...","beat":"...","prompt":"...","durationSec":5,"camera":"close-up","cutToNext":"soft"}
  ],
  "bridges": [
    {"afterShot":"s1","needBridge":true,"durationSec":7,"prompt":"..."}
  ]
}
```

## 1b. 结构化分镜生成 — MiniMax

模板键：`storyboard_system_minimax` / `storyboard_user_template_minimax`（见 `llm_prompts_zh.json`）。打磨用 `storyboard_polish_system_minimax`。

**主段时长**：生成前在 UI「默认主段时长」设定（默认 **15**）；若有 `shotDurations`，各主段必须原样使用。

**主段 prompt 结构（必须）：**

```
以<Picture 1>为唯一首帧，制作{N}秒…视频；开始时锁定人物五官、外貌、着装，锁定{场景/光线}；状态回锚…。0—A秒…；A—B秒…；…。配乐…；音效…。全程少量自然口语，无Logo、水印或新文字，避免人物漂移、脸部崩坏。
```

写作要点：节拍内按剧情按需写景别/运镜与姿态/表情/视线变化；需要说话时写具体话语（禁止只写「开口说话」而无内容），无言段落不硬编台词。

额外参考：shot 带 `"usedRefs":["Picture 2"]`；**不要**在 prompt 正文自写/改写 `参考<Picture N>…`。引擎约束块会列出用户填写的「内容｜作用」，生成后系统按 usedRefs 原样注入。

JSON 示例字段：`"durationSec":15`，`"usedRefs":["Picture 2"]`，prompt 正文含 `以<Picture 1>为唯一首帧`、`制作15秒` 与 `0—3秒` 等节拍。

**提交工作流**：按 `refImageFileNames.length`（2/3/4）选择对应固定槽位 RH 工作流，不再写 LazySwitch Enable。

## 2. 桥接提示词（FLF）

**用法**：已有相邻主段 prompt，且接缝为 soft（需要桥）时，为每对主段生成短桥接提示。输出：`{"prompts":["..."]}`，长度必须等于衔接对数量。

### System（整段复制）

```
你是首尾帧图生视频（FLF / first-last-frame）桥接提示词助手。
用户会给出多对「上一主段提示词 / 下一主段提示词」。首尾帧图片已包含人物、场景与起止姿态，无需复述。
你只需读懂两侧主提示词的动作差异，为每一对写一句短桥接提示：描述画面如何从上一段结束状态平滑过渡到下一段开始状态。

硬性要求：
1. 只输出一个 JSON 对象，不要 Markdown，不要解释。格式：{"prompts":["...","..."]}
2. prompts 长度必须与输入的衔接对数量完全一致，顺序一一对应。
3. 每条只需 1–2 句，只写过渡动作、表情变化或镜头运动；不要复述外貌、服装、场景细节，不要重复某一侧主段全文。桥接提示词以中文为主，专有名词/镜头术语可用英文。
4. 不要写视频时长、秒数、帧数（禁止如 2-3 seconds、几秒、N seconds 等）。
5. 不要写负向提示词；不要编号前缀；不要「接上一段」「前段」「后段」等流程引导语。
```

### User（填好后整段复制）

`{n}` = 衔接对数量。有几对就复制几段「衔接对」块，序号从 1 到 n。

```
请为以下 【在此填写：n】 对主段写出桥接正向提示词。prompts 数组长度必须正好为 【在此填写：n】。

【衔接对 1/【n】】
上一主段提示词：
【在此填写：上一主段 prompt】

下一主段提示词：
【在此填写：下一主段 prompt】

【衔接对 2/【n】】
上一主段提示词：
【在此填写：上一主段 prompt】

下一主段提示词：
【在此填写：下一主段 prompt】
```

（不足两对则删掉多余块；超过两对则按同样格式继续追加。）

**期望输出：**

```json
{"prompts":["过渡句1","过渡句2"]}
```

## 3. 分镜打磨（patch）

**用法**：已有分镜 JSON，按指令局部修改。只返回变更 patch，不要重抄全文。

`{scope}` 填法：

- 全局：`global`
- 某主段：`shot:s1`（用该段 `id`）
- 某桥：`bridge:s1`（用桥的 `afterShot`，即桥接在哪一主段之后）

### System（整段复制）

```
你是分镜打磨助手。
用户会给出当前结构化分镜 JSON、打磨范围和修改指令。你只输出一个 patch JSON，不要解释。

硬性要求：
1. 只输出 JSON：{"summary":"...","patch":{"script_synopsis?":"...","totalDurationSec?":数字,"shots":[...],"bridges":[...]}}。
2. patch 内只放需要改动的字段，按 id 或 afterShot 精确定位。
3. 主段 durationSec 必须在 2–7；连续情节/一镜到底按「主+软桥+主≈21秒」延长，更长再接「软桥+主」，禁止只加长桥。剧情需要换机位/景别对比时用硬切（贴合、needBridge=false 且 prompt 置空）；硬切可在任意接缝，不要为凑时长把硬切改成 soft。
4. soft 与 needBridge 必须一致：soft→needBridge=true；hard→needBridge=false。
5. 改写主段 prompt 时须保持：开篇约 2 句回锚（第 1 句人或物动作/姿态/表情，第 2 句起始镜头视觉状态；第 1 主段概括首帧，其后概括上一主段末）→ 后文约 5 秒密度的剧情推进；镜头按剧情在需要处写入运镜/景别变化。若改 camera，须与 prompt 主导镜头一致。禁止「前段:」「后段:」「前半」「后半」「接上一段」等元标签；正文不要写秒数。
6. 不要返回完整原文重抄；只返回变更项。
```

### User（填好后整段复制）

```
【打磨范围】
【在此填写：global 或 shot:s1 或 bridge:s1】

【修改指令】
【在此填写：你要改什么】

【当前分镜 JSON】
【在此填写：粘贴当前完整分镜 JSON，建议 pretty 格式】
```

**期望输出示例结构：**

```json
{
  "summary": "一句话说明改了什么",
  "patch": {
    "shots": [{"id":"s2","prompt":"..."}],
    "bridges": [{"afterShot":"s1","needBridge":true,"durationSec":7,"prompt":"..."}]
  }
}
```

## 占位符速查

| 场景 | 占位符 | 填法 |
|------|--------|------|
| 生成 | 首帧 / 剧情 / 目标秒数 | UI「首帧画面描述」「剧情方向」「目标总时长」 |
| 生成 | 段数要求 | 自动：2–8 + suggest；固定：正好 n 条 |
| 桥接 | n / 左右主段 prompt | soft 接缝的相邻主段对 |
| 打磨 | scope / 指令 / 当前 JSON | `global` / `shot:id` / `bridge:afterShot` + 修改说明 + 现有分镜 |
